# Five tests before any candidate

Before looking at ideas, I set the tests an idea would have to pass:

1. **Data moat.** It has to run on data only the system of record holds: work orders, labour, parts, financials. If someone outside could build it without DockMaster's data, it fails.

2. **A named buyer who already feels the pain.** A specific person at the marina who is losing money or sleep over this today. Then selling is showing them something they already want.

3. **Revenue mechanics that hold up.** It can be sold as an add-on to the ~650 marinas and ~4,000 users already paying for DockMaster, at a price the customer can compare to a cost they already know.

4. **A small team can build it.** A first sellable version has to be deliverable against a legacy hybrid platform. No data-science department, no rebuild of the platform first.

5. **Portfolio leverage, both directions.** Inbound: which existing group AI capabilities can be reused here. Outbound: does what we build become something the group can use again across its ~170 software companies. Reuse before build, and build things that can be reused.

### Deliberately not a test: whether it uses AI

An idea scores nothing for having AI in it. If a scheduling algorithm or a plain report solves the problem more cheaply, the AI idea loses. This keeps us from reaching for AI out of habit.
